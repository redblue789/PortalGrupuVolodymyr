# Табло подій — портал групи (Django)

Готовий Django-проєкт: стрічка подій + календар подій на фронтенді,
і повноцінна адмін-панель Django для керування подіями.

- **Всі користувачі** бачать стрічку подій (`/`) і календар (`/calendar/`).
- **Адміністратори** (`is_staff` / суперкористувачі) мають доступ до
  вбудованої адмін-панелі Django (`/admin/`) і до кнопок «Додати / Редагувати /
  Видалити» на фронтенді.
- **Модератори** — це звичайні користувачі, додані в групу `Moderators`
  (створюється автоматично після першої міграції). Вони НЕ бачать `/admin/`,
  але мають ті самі кнопки керування подіями на фронтенді.

## Запуск у PyCharm

1. Розпакуйте архів і відкрийте папку `events_portal` як проєкт у PyCharm
   (`File → Open…`).
2. Створіть віртуальне середовище: `File → Settings → Project → Python
   Interpreter → Add Interpreter → Add Local Interpreter → Virtualenv`,
   базуючись на будь-якому Python 3.10+.
3. Відкрийте вбудований термінал PyCharm (`Alt+F12`) і встановіть залежності:

   ```bash
   pip install -r requirements.txt
   ```

4. Застосуйте міграції (створить `db.sqlite3` і таблиці, а також групу
   `Moderators`):

   ```bash
   python manage.py migrate
   ```

5. Створіть обліковий запис адміністратора:

   ```bash
   python manage.py createsuperuser
   ```

6. (Необов'язково) завантажте кілька демонстраційних подій:

   ```bash
   python manage.py loaddata sample_events
   ```

7. Запустіть сервер розробки (кнопка ▶ біля конфігурації Django, або):

   ```bash
   python manage.py runserver
   ```

8. Відкрийте у браузері:
   - **Портал (стрічка + календар):** http://127.0.0.1:8000/
   - **Адмін-панель Django:** http://127.0.0.1:8000/admin/ — увійдіть під
     обліковим записом суперкористувача з кроку 5.

## Як призначити модератора

Модератор керує подіями на фронтенді, але не заходить в адмін-панель:

1. Увійдіть в `/admin/` під адміністратором.
2. Розділ **Users** → створіть або відкрийте користувача.
3. У полі **Groups** додайте групу **Moderators** → «Save».

Тепер цей користувач, увійшовши через `/accounts/login/` (кнопка «Увійти»
на порталі), побачить кнопки «Додати подію», «Редагувати», «Видалити».

## Структура проєкту

```
events_portal/
├── manage.py
├── requirements.txt
├── config/                  # налаштування проєкту (settings, urls)
├── events/                  # застосунок: модель Event, admin, views, шаблони
│   ├── models.py            # модель Event (дата, час, категорія, статус…)
│   ├── admin.py             # реєстрація в адмін-панелі Django
│   ├── views.py             # стрічка, календар, додавання/редагування/видалення
│   ├── forms.py
│   ├── urls.py
│   ├── migrations/
│   ├── fixtures/sample_events.json
│   ├── static/events/css/style.css
│   └── templates/events/
└── templates/                # базовий шаблон + сторінка входу
```

## Примітки

- База даних — SQLite (`db.sqlite3`), файл створюється локально після
  `migrate` і не потрапляє у git (див. `.gitignore`).
- `SECRET_KEY` у `config/settings.py` придатний лише для локальної
  розробки — перед розгортанням у продакшн згенеруйте новий та винесіть
  його в змінну середовища.
- Categorії подій, статуси та кольори тегів можна змінити у
  `events/models.py` (класи `Event.Category`, `Event.Status`).
